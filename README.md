# 日韩 11 日行程拖拽规划器

纯静态 GitHub Pages 页面：

- “行程排布”页签支持上午、下午、晚上之间拖动、同栏排序、词条库、回收站撤销及 PNG/JSON 导出。
- PNG 提供 2400×1800 横版总览与竖版明细两种版式；横版采用广安里夜景与阿苏草千里双景横幅、4＋4＋3 日历卡和一张出发前检查卡。
- “时间明细”页签按天展示建议开始时间、预计耗时、转场缓冲和待确认航班节点。
- “景点汇总”页签按釜山、熊本、福冈、首尔的行程顺序展示计划景点、日期、类型与地区游览提示。
- 当前基线为 2026/9/25–10/5；釜山加入广安里夜景，九州改为先熊本、后福冈，并保留阿苏、大濠公园、福冈城遗址与 LaLaport 实物大 ν 高达。
- 商业化响应式界面包含旅行路线 Hero、行程统计、吸顶导航、可折叠词条库和城市优先的日程卡；桌面端在 Hero 集中导出，移动端通过底部面板选择横版、竖版或 JSON。
- 数据层拆分为 `trip-data.js`（基线与词条）、`trip-content.js`（时间轴与景点内容）和 `trip-store.js`（版本化状态、校验、迁移与持久化）。
- 用户调整结果与自定义词条统一保存在 `jk-trip-planner-state-v1`；首次打开会自动迁移旧版 localStorage，并在过渡期兼容写入旧键，数据不上传服务器。

数据层回归测试：`node tests/trip-store.test.js`

## 行前准备功能

- “行前指南”按风险提示、釜山、熊本与阿苏、福冈、首尔、入境与随身准备分区，提供建议时长、路线重点、预约要求、天气风险、替代方案和官方入口。
- “背景速读”按釜山、熊本与阿苏、福冈、首尔整理18张一分钟阅读卡，分别说明为什么值得看、必要背景、现场观察重点与关键词。
- “预约确认”统一管理航班、酒店、跨城交通、门票、动态开放状态和入境资料；每项支持“未开始、待确认、临行复核、已完成、不需要”五种状态。
- 确认状态保存在统一浏览器状态的 `confirmations` 字段中，随完整行程 JSON 一起导出；更新基线或恢复行程不会清空准备进度。
- “个人备忘”用于记录用户自己的通信、换汇、交通卡、行李、证件和购物事项，支持新增、编辑、完成、筛选、删除与撤销。

## 界面精修

- 桌面与移动端采用同一套商业化视觉体系；移动端首屏、路线轴、横滑导航和背景速读卡均有独立响应式排版。
- 上午、下午、晚上及交通状态使用统一 SVG 图标；空白时段自动压缩，并以城市辅助色和“移动日”标识强化行程扫描效率。
- 保存、导出与确认操作提供轻量状态反馈，页脚展示内容更新时间与临行复核提示。
- 景点汇总与背景速读使用四张本地 WebP 地区横幅；首页加入低干扰路线纹理，图片署名与许可集中展示在页脚。

## 个人备忘云同步

- “个人备忘”支持可选的 Supabase 邮箱 Magic Link 登录；未登录时仍完全按原逻辑保存在本机，登录后才会同步。
- 云端只使用独立表 `public.jk_trip_notes`，并通过 RLS 限制为当前用户自己的行；首次启用请在 Supabase SQL Editor 执行 [`supabase/personal-notes.sql`](supabase/personal-notes.sql)。
- 在 Supabase Authentication 的 URL Configuration 中加入 `https://lihuasi101-beep.github.io/japan-korea-trip-planner/`，再从网站“个人备忘”页输入邮箱登录。
- 前端只使用 Supabase publishable/anon 公钥；不要把 `service_role` 或 `sb_secret` 密钥放进静态站点。
- 个人备忘保存在统一状态的 `personalNotes` 字段中，不预置用户示例内容，也会随完整行程 JSON 导出。
